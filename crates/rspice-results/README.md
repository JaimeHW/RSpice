# rspice-results

Exact result data and the viewer-independent rules over it: retained runs and
analysis results, per-analysis evidence, family and statistical projections,
specification verdicts, waveform calculations, and the versioned visualization
and report documents a viewer presents. Producers (`rspice-simulation`),
viewers (`rspice-results-ui`, `rspice-hardcopy`), persistence and interchange
(`rspice-project`, `rspice-formats`) and the CLI all share these values, so a
retained number has one owner and one validation rule.
`tools/ci/check_app_crate_dependencies.py` allows it only `rspice-app-types`
and `rspice-units` among the application crates, and refuses egui, eframe,
winit, wgpu and rfd in its closure.

## What's in here

| Module | Contents |
| :--- | :--- |
| `run`, `run_history`, `run_receipt`, `provenance`, `manifest`, `executed_deck` | `SimulationRun` and its lifecycle; `RunHistory` with retention and revision tracking; what a run executed against, by model-source digest; the prepared task and PVT point a result came from; dataset manifests; retained executed decks |
| `analysis_result`, `analysis_payload`, `validation`, `result_digest` | `AnalysisResult`, the retained samples and scalar evidence of one analysis; exact per-analysis payloads; cross-field validation; and canonical content digests that exclude presentation-only waveform attributes |
| `analysis_type`, `analysis_tag`, `simulation_values`, `spice_value` | Analysis kinds and their SPICE spellings; the closed numeric analysis-tag protocol; solver-independent retained values; the scalar SPICE value parser, which takes its suffix scale from the engine's lexer |
| `operating_point`, `dc_sweep`, `dc_mismatch`, `transfer_function`, `sensitivity`, `noise`, `noise_spectrum`, `phase_noise`, `pole_zero`, `network_matrix`, `floquet`, `harmonic_spectrum`, `fft`, `events`, `current_impulses`, `voltage_impulses` | Retained evidence for each analysis family. `fft` also holds the window functions and, with `engine-evidence`, the uniform-resampling input pipeline, the transform and the derived THD, SNR, SFDR and ENOB figures |
| `convergence_quality`, `convergence_attribution`, `transient_checkpoint`, `monte_carlo_checkpoint` | Numerical quality retained with a transient; the objects a failed run names on the drawing; portable accepted transient state; durable Monte Carlo trial journals |
| `family_metadata`, `family_projection`, `family_measurements`, `population`, `monte_carlo`, `yield_analysis`, `histogram` | Swept, corner and trial families: retained coordinates and typed filters, per-member measurements, population statistics and requirement margins, Monte Carlo mean intervals, yield, and histogram construction and plot geometry |
| `specification`, `specification_verdict`, `optimization`, `safety`, `soa_evidence`, `soa_source`, `eye_mask` | Requirement definitions and the sealed verdict of a prepared run; optimization terms and observations; safe-operating-area rules, curves and violation evidence; eye compliance masks in absolute units |
| `calculator`, `measurements`, `interpolation`, `sampling`, `waveform_comparison` | The waveform expression parser, evaluator and function library; interval statistics; interpolation on a strictly monotone axis; `SweepShape`, the monotone-branch analysis of an X column; aligned comparison and difference of retained results |
| `bode`, `nyquist`, `stability` | Frequency-response and Bode margin mathematics, the closed Nyquist contour and its encirclement count, and the margin conventions the Bode and Nyquist readings share |
| `waveform`, `saved_output`, `result_import` | `RetainedWaveform` and `WaveformData`; policies and source identities of saved outputs; source attribution for imported external datasets |
| `visualization_document`, `report_document`, `document_creation`, `result_presentation`, `engineering_table` | `VisualizationDocument`, the versioned presentation over immutable datasets; `ReportDocument`, pages, sections and blocks with linked or frozen references; result document families and initial layouts; durable presentation identities and annotations; engineering-table views shared by rendering, clipboard and export |
| `visualization_raster` | Deterministic software rasterization of one report figure to PNG, identical on native and WebAssembly; unsupported features are refused rather than omitted |
| `viewer_catalog` | `VIEWER_DOCUMENTS` and `RESULT_CREATION_FAMILIES`, generated by `build.rs` from `contracts/result-data-contract.json`, and `viewer_compatibility` against a caller-supplied capability snapshot |
| `number_format`, `plot_axis` | SI-prefixed number formatting for axes and readouts; axis scales and tick generation |

## Boundaries

- Result viewers and their display sessions belong to
  [`rspice-results-ui`](../rspice-results-ui); binding them to the project's
  run and dataset selection belongs to [`rspice-app`](../rspice-app).
- File codecs (CSV, VCD, HDF5, PSF and the rest) and versioned project result
  persistence belong to [`rspice-formats`](../rspice-formats).
- Running analyses belongs to [`rspice-simulation`](../rspice-simulation) and
  [`rspice-core`](../rspice-core); the `.FFT`, `.SENS` and other engine-computed
  values retained here are mirrors of what the engine returned.

## Entry points

- `run::SimulationRun` and `run_history::RunHistory` for retained runs.
- `analysis_result::AnalysisResult` for one analysis's retained data.
- `calculator::parser::try_parse(input, parse_number)`, then
  `calculator::evaluator::evaluate(&expr, &context)`.
- `VisualizationDocument::new(title, datasets)`, then
  `transact(expected_revision, edits)`; a failed transaction leaves the
  document unchanged.
- `ReportDocument::new(title)`, then
  `transact(expected_revision, edits, timestamp_unix_ms)`.
- `visualization_raster::render_visualization_report_figure` for a figure PNG.
- `viewer_catalog::viewer_document(id)` and `viewer_compatibility`.
- `result_digest::dataset_content_digest` for a dataset's content identity.

## Feature flags

| Flag | Effect |
| :--- | :--- |
| `engine-evidence` | Adds the modules that retain engine-backed observations and their canonical validation (runs and run history, analysis results and payloads, result digests, specifications and verdicts, FFT computation and the rest), pulling in `rspice-core`, `rspice-design-model` and `rustfft`. Document and calculation consumers can omit it |

## Testing

```bash
cargo test -p rspice-results
cargo test -p rspice-results --features engine-evidence
```

The second run covers the engine-backed modules, which the default build
leaves out.
