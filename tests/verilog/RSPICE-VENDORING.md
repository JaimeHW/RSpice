# RSpice Verilog Oracle Corpus — Provenance

The digital Verilog cases compared against Icarus Verilog and Verilator by
`crates/rspice-conformance/src/suites/verilog.rs`.

Named for the language rather than for the domain, and not arbitrarily:
`tests/paranoia/digital/` already exists as a sub-corpus, and its manifest keys
begin `digital/`. A second, top-level `tests/digital/` would have collided with
it in every grep.

Unlike its neighbours this directory is almost entirely **RSpice-authored**, so
it is a provenance note more than a vendoring note. Only one file derives from
outside material, and the reason it is the only one is recorded below.

## Licensing

**Every file here is RSpice's own work and ships under the repository's
license**, with the single qualification discussed under `c17.v`. There is no
unresolved third-party status in this directory, deliberately — see
`../iscas85/RSPICE-VENDORING.md` for what that costs when it goes the other way.

## `c17.v`

`c17.v` reproduces the ISCAS85 c17 benchmark: six 2-input NAND gates wired in
the arrangement published with the 1985 benchmark set. The file was written for
this corpus rather than copied; what is taken from outside is the circuit
topology, which is six gates, is stated identically in every textbook and paper
that uses it, and is a fact about a circuit rather than an expression of one.
The comments, port ordering, instance names, and formatting are RSpice's.

That is a deliberately narrow claim, and it does not extend to the rest of the
benchmark family.

## The rest of ISCAS85 is *not* here, and that is a decision

c432, c499, c880, c1355, c1908, c2670, c3540, c5315, c6288, and c7552 are
absent. They are widely mirrored as gate-level Verilog, but the mirrors are the
problem rather than the solution:

- The original ISCAS85 distribution carries **no license**. Redistribution has
  been universal since 1985 and remains ungranted; an absence of complaints is
  not a grant.
- The GitHub and university mirrors that do carry a license file are asserting
  terms over material they did not author. A permissive license applied by a
  redistributor conveys nothing the redistributor did not hold.
- The copies most easily fetched are **synthesis tool output** — the widely
  mirrored `c17.v` carries a `Generated by Cadence Genus(TM) Synthesis Solution`
  header — which adds a second party's interest to a file that already had an
  unclear first one.

RSpice already carries one corpus in this condition: `../iscas85/` vendors the
transistor-level SPICE renderings and its note records the status as unresolved
and **owed before any release that ships the `tests/` tree**. Importing the
gate-level Verilog from the same benchmark family would enlarge that liability
rather than add a new capability, because what those circuits buy is *scale*,
and scale is not what this corpus is for. The authored cases here are chosen for
*language coverage*: each one isolates a construct the front end must implement.
A 3512-gate netlist of 2-input NANDs exercises nothing that `c17.v` does not.

If scale coverage is wanted later, the honest acquisition step is to fetch on
demand in CI rather than vendor — the option `../iscas85/RSPICE-VENDORING.md`
already names — and to resolve both corpora's status in one decision.

## Corpus layout

Each case is a pair of files sharing a stem:

- `<case>.v` — the design under test. Structural or behavioural Verilog with
  no `$display`, no `$monitor`, no `initial` block, and no delays. Everything
  observable travels through the module's ports.
- `<case>.stim` — the port declarations, timing, and input vectors, in the
  `RSPICE-VERILOG-STIMULUS 1` format.

`verilog-manifest.tsv` lists every case and the oracles it may be compared
against.

The testbench is **generated, never checked in**. Both oracles receive a
testbench synthesised from the `.stim` file by the harness, so the printing
format is owned by RSpice and is identical across simulators rather than being
each simulator's idea of how to format a number. The format, the timing rules,
and the trace grammar are specified in the module documentation of
`crates/rspice-conformance/src/suites/verilog.rs`, which is the code that has to
honour them.

## Oracle binaries

No oracle output is checked in, because none has been captured: neither Icarus
Verilog nor Verilator was installed on the machine where this corpus was
authored, and a checked-in oracle whose producer nobody has run is worse than
none. The harness detects their absence and reports it. Once the binaries are
available the intended maintenance step mirrors the ngspice corpora — capture
sidecars beside each deck, record the producing version and its digest here —
and this note gains a regeneration recipe at that point.
