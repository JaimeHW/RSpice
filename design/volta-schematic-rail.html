VOLTA — schematic rail: navigator + library

01 · The rail at work

One rail, two contexts — and placement that never leaves it

Navigator answers “where am I, what is here”: the nameplate pins the open cellview, instances expand to peek into their masters, E descends and the occurrence path appears as a first-class strip. Library answers “what can I place”: palette categories with real symbol artwork, project and vendor libraries, pins and a stable preview. The place strip at the bottom belongs to both — press i, type three letters, ⏎, drop. Everything below is live: descend into X1, probe the nets, place an instance on the canvas.

Implementation. Replaces all three sections of shell/panels/schematic.rs. The nameplate and occurrence path read workspace.active_view and workspace.hierarchy_stack (both exist today); peek rows resolve the master through LibraryManager the same way descend already does. Nets/Ports need one new index — the inverse of net_mapping (name → positions), rebuilt on topology change. The library tab keeps the CELL_CACHE keyed filter but groups by the palette sections that component_palette.rs already declares; thumbnails reuse the shipped assets/component_symbols SVGs through the existing usvg pipeline. Recents and pins are two small Vec<CellEntry> in ShellState, persisted with the workspace. The place strip reuses the focus_cell_search one-shot; Enter arms the same Tool::Place path the Place button uses today.
02 · Anatomy

Seven zones, one reading order

The rail reads top-to-bottom the way an engineer asks questions: which context → which cell → where in the hierarchy → what am I looking for → the design itself → what do I place next. The descended state shown here is the busiest the rail ever gets — there is no fourth tab, no second accent, and nothing that appears or disappears except the occurrence path, which is the one state worth shouting about.

  1. 1Context tabs. Two contexts, never more: the design you are editing, the shelf you place from. Both keep the place strip, so switching is rare by design.
  2. 2Nameplate. Library, cell and view of the open sheet plus live counts — the counts come from the same model as the tree, so they can never disagree with it.
  3. 3Occurrence path. Appears only when descended — the single stateful surface, and the only accent-washed one. Crumbs jump, U ascends. Maps 1:1 to workspace.hierarchy_stack.
  4. 4Find in design. One query across instances, nets and ports; matches are marked in place, grouped by kind, and stay click-to-cross-probe.
  5. 5Kind segments. Instance-centric and net-centric navigation are equal citizens — Spectre users debug by net name as often as by instance.
  6. 6Hierarchy rows. The twist peeks into a master (ghost rows, read-only — cheap to look, impossible to edit by accident); E or double-click descends. Meta column carries value or master, right-aligned, always mono.
  7. 7Place strip. The most-used action in any schematic session gets permanent geometry: command slot with typeahead, recents as chips. The armed chip is the same accent-dim treatment as a pressed tool.
Implementation. Zones 2–3 are two short widgets over CellViewRef + hierarchy_stack; zone 5 is a three-way seg on the existing selection model; zone 6 extends TreeRow with a twist slot and a ghost style — peek resolves the master via LibraryManager exactly like open_selected_instance_master() but renders instead of navigating. The descend affordance reuses the canvas gesture in schematic/view/interaction.rs. Row heights stay t.metrics.row_h, type stays FS_0/FS_1, and every fill in this figure is an existing token from ui/palette.rs — no new colors were introduced.

04 · Interaction map

Keyboard-first, mouse-equal

Every rail action has a key, and every key has a mouse path of equal rank. Nothing here invents a new grammar: W/N/P ship today, descend extends the double-click the canvas already owns, and i extends the Create-menu search focus that exists in the shell.
