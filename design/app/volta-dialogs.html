One dialog grammar for the whole simulator

The IDE shell, results workspace, and canvas already speak VOLTA. Every window the app opens still speaks 2009-era defaults. This spec defines the single modal primitive they all port onto, and redesigns the surfaces that deserve more than a re-skin: analysis configuration moves into the Simulate view, property editing collapses to one surface, and the three diagnostic viewers adopt the plot grammar. Tokens are lifted verbatim from ui/palette.rs (Instrument · dark shown).

01

Modal grammar

Every dialog is the same three-part surface over a scrim. No floating windows that can be dragged off-screen and lost; no two dialogs with different button orders.

PartRule
ScrimFull-viewport, canvas-black at 55%, subtle blur. Click does not dismiss (explicit actions only); Esc cancels.
Surfacebg_panel, 1px border_strong, 6px radius, pop shadow. Widths: sm 400 · md 560 · lg 780. Max height 82vh, body scrolls.
HeaderMono uppercase kicker (domain) + sans-semibold title + close. Close is the only chrome control.
FooterLeft: mono hint (validation count, shortcut). Right: [ghost] [secondary] [primary]. Primary is always rightmost, always exactly one, accent-filled. Destructive primaries use err.
KeysEsc = cancel · Enter = primary (when valid) · focus trapped inside; first field focused on open.
CommitDialogs edit a draft and commit on primary. OK and Cancel are never the same operation.

02

Confirmations

The save-changes prompt is the template instance of the grammar: small surface, one sentence, three explicit verbs. Destructive choice is never the primary.

LIVE

Library deletions get the same surface with a destructive primary and the cell name echoed in mono — the design currently has deletion plumbing with no confirmation at all.

03

Analyses live in the Simulate view

The 700×520 “Simulation Setup” window with 25 tabs is retired. The Simulate view’s analyses card is the single source of truth: a row per analysis with an enable switch and a mono summary of its parameters; selecting a row opens its typed form in the right panel. “Add analysis” is a searchable picker, not a tab strip.

ElementRule
Rowswitch · mono id (TRAN, AC, …) · name · right-aligned mono parameter summary. Invalid configs show the error count in err instead of the summary.
FormRight panel, registry-driven rows: label / mono input / unit. Validation inline per field on edit; the Run bar refuses to run while any enabled analysis is invalid.
Picker＋ opens an md modal: search box + category-grouped cards. Choosing one enables it and selects its form.
StateTyped per-analysis configs (no string-buffer god-struct). Draft-free: the view is the config; undoable like any state.

05

Instance properties — one surface

Three competing editors become one: the shell Inspector stays primary for quick edits (undo-tracked, always visible); this dialog is the advanced editor opened by double-click or E. Registry-driven rows, inline validation, modified markers, and the PWL table — no second “simple” dialog.

ElementRule
Rowlabel / typed editor / unit. Modified fields show an accent dot before the label; errors render under the row in err — never raw YELLOW/RED.
Modelmodel fields get a trailing Browse ghost button → Model browser (06) in picker mode.
PWLa real data table: mono columns, row hover, add/delete as ghost buttons in the header, footer summary (points · t-range · v-range).
CommitApply / Cancel / Revert; Apply commits one undo entry (session pattern shared with the Inspector).
LIVE
06

Model browser

Same information architecture it always had — libraries → models → detail — rebuilt with the Library view’s vocabulary: tree rows, mono metadata, a detail pane of stat tables. Corner selection is a chip row. Opens standalone (Tools) or as a picker from the property editor.

LIVE
07

Small forms

New Cell, New View, the Verilog-A loader, and PDK settings are sm/md instances of the grammar: section headers, field rows, footer verbs. No emoji buttons — actions use the icon set or words. New View arrives pre-filled from the Library selection (today it opens blank and can’t submit).

LIVE

PDK settings keeps its four tabs on the docbar tab pattern; file-type badges become mono chips in token colors; “Rescan” is a normal button with a progress spinner in the footer hint slot. About/Shortcuts/Calculator are mechanical ports of the same shapes.

08

Probe feedback

Probing currently reports into the console only — collapsed console, silent feature. Every probe action gets a toast (bottom-right, above the status bar), and probed nets render a small mono chip at the click point for one second. Toasts carry one optional action.

CaseToast
Wire hitok dot · “Probing net out” · sub: “V(out) added to WAVES” · action: View → Results.
No data yetwarn dot · “No waveform for V(out)” · sub: “Run a simulation first” · action: Run.
Groundinfo (text_dim) dot · “net 0 is the ground reference”.
LIVE
09

Diagnostic viewers on the plot grammar

Nyquist, Smith, and pole-zero drop their private hardcoded palettes and rebuild on the plot engine exactly like BODE/FFT: token grid and frame, decimated token traces, bordered marker tags, stats in the right panel — numbers never float over curves. They keep their geometry, not their chrome.

ViewerTreatment
NYQUISTSquare plot, unit circle as ref-line ring, −1 point as an err marker tag; encirclement count + GM/PM in the right panel (cached per data version).
