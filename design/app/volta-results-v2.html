01 · Run shelf

Results are keyed by run

The shelf is the workspace's data model made visible: each row is one run with status, progress, and an overlay toggle that feeds every viewer below. The live Monte-Carlo row streams its sample count while running — waveforms appear as they compute, never after. Hover a row to focus that run everywhere; the focused run renders at full strength.

bench ota_5t.tb history 7 runs
ovlrunstatus progressanalysisactions
Implementation: a RunId-keyed ResultsStore replaces state.simulation.* singletons; every viewer reads store.overlaid() + store.focused(). Live rows subscribe to the streaming channel the engine already exposes for progress. Checkpointed rows resume via rspice run --restore.
02 · Overlay

Signal owns hue · run owns weight

Five corners of the OTA step response, one signal. The trace keeps its hue across runs; only the focused corner draws at full strength. Hover a legend chip (or move the crosshair) — the readout lists one row per run, ranked, with deltas against nominal. Numbers stay in the right panel; the canvas stays clean.

03 · Specs matrix

Tests × corners, specs on the rail

Rows are .meas results, columns are corner runs, the rail holds spec bounds. Failing cells tint; the worst violator carries a ring. Click a failing cell — the workspace focuses that corner in the shelf, the overlay, and the readout. One click from “which corner fails” to “what the waveform did”.

06 · OP inspector

Per-device operating points

The Spectre-style OP info (engine: device_op_report) as a workspace surface: region chips, engineering notation, filter and column sort. Rows are cross-probe handles — hovering one highlights the device's net on the schematic.

run tt · .op
Cross-probe contract: row hover emits CrossProbe::Device(name) on the workspace bus; the schematic canvas subscribes (net highlight), as does the netlist view (line highlight). Same bus the waveform legend already uses in the other direction.
